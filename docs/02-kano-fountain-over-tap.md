# 02｜Kano 与 Fountain-over-Tap

## 1. 先定义竞争对象

`Tap` 是一次性取水：用户输入 Prompt，FM 返回一个文件，价值在下载/播放处结束。

`Fountain` 是持续出水：用户每次确认的角色、事实、关系、参考集和版本，会让下一次生成更快、更少重讲、更容易检查；每个接受的输出都会增加 World 的可用资产，而不是只增加一条孤立历史记录。

产品不是“生成更多”，而是“**每次生成都会让下一次更值得回来**”。

## 2. Kano 模型

### Must-be：没有就不信任

| 需求 | 用户可见承诺 | 验证方式 |
|---|---|---|
| 结果可用 | 下载/播放链接不失效，输出规格正确 | 端到端可用性、空文件率 |
| 价格可预测 | 开始前显示最高估算，完成后显示实际结算 | 最高额与实际账单的差异 |
| 技术失败不收费 | provider 失败、空文件、严重硬约束失败不消耗最终费用 | 失败账本审计 |
| 资产归属清楚 | 每个 World/Asset 只能被拥有者读取、下载、删除 | ownership 测试 |
| Canon 不被污染 | AI 建议不能未经确认变成事实 | accepted/proposed 状态审计 |
| 可恢复 | 队列失败、重试、并发限制不会造成重复扣费 | 幂等与故障注入 |
| 基础复用 | 上次确认的实体能在下一次被选用 | 引用率与任务记录 |

### Performance：做得越好越有价值

| 需求 | 核心衡量 |
|---|---|
| 首次可接受率 | 第一次 Preview/Final 不需要推倒重来 |
| 一致性 | 角色、地点、物件和世界规则的硬约束违反率 |
| 速度 | 从提交到 Preview、从批准到 Final 的 p50/p95 |
| 成本 | 每个最终接受资产的 provider 成本 + FM 成本 |
| 资产复用 | 既有实体/参考集在后续生成中的使用比例 |
| 转换效率 | 从“想法”到“已批准资产”的分钟数 |
| 连载稳定性 | 同一 World 7 日/30 日活跃和重复发布 |

### Attractive：能形成“我为什么要用 FM”

| 需求 | 体验表现 | 为什么可能防御 |
|---|---|---|
| Contract Preview | 在花钱前显示“本次必须保留/允许变化/冲突” | 是结构化决策，不是模型按钮 |
| Canon Diff | 一眼看到“新输出建议新增、修改或冲突的事实” | 有历史、来源和批准状态 |
| 一键 Promote | 把接受的角色/参考集/事实提升到 World | 让一次生成转成未来资产 |
| H3 Max Preview | 便宜快速地试动作/节奏，不必先烧 Final 成本 | 模型变强时 FM 体验受益 |
| 跨模型 portability | World 的实体与参考集可以换执行器仍能用 | 用户锁定的是自己的状态，不是供应商 |
| 关系/状态时间线 | 角色关系和状态会随章节推进 | 不是单张图能替代的对象 |

### Indifferent：不应占据首页

- 11 个模型的选择器、供应商名称、随机路由细节。
- MCP 本身作为营销主张。
- 大量输出格式、复杂风格下拉框、无实际决策作用的仪表盘。
- 把“点数、额度、不同模式”全部暴露给用户。

### Reverse：做了反而伤害信任

- 强迫用户在第一次生成前创建完整 World。
- 生成后自动把 AI 猜出的内容写入 Canon。
- 强制 1 小时删除，让用户来不及比较或提升资产。
- 把技术失败、不可播放文件和主观不喜欢都写成“不可退款”。
- 把 B2B 包装成“固定价格，直到你喜欢为止”。
- 用“AI 魔法”或反 AI 口号替代清楚的控制与所有权。

## 3. Fountain 的最小闭环

```text
意图
  ↓
选择 World / 或留在 Scratch
  ↓
读取 Canon、关系、参考集和目标状态
  ↓
生成 Contract：硬约束、允许变化、Preview/Final、最高估算
  ↓
Reserve max → 执行器（H3 Max / H3 / fallback）→ 技术验证
  ↓
Preview：用户判断方向
  ↓
Final：按真实成本结算
  ↓
用户批准：保存输出；可选 Promote 到 Entity / Canon / Reference Set
  ↓
下一次生成携带更多可靠状态，减少重讲与盲试
```

注意：生成结果可以被保存而不升级为 Canon。**用户接受媒体**和**用户确认事实**是两个不同动作。

## 4. 如何击败更快的模型

不是和 H3 Max 比“谁 3 秒更快”，而是改变比较单位：

| 供应商比较 | FM 比较 |
|---|---|
| 一次 clip 的画面质量 | 一个最终接受资产的总成本 |
| 生成 API 延迟 | 从意图到批准结果的时间 |
| 参考图数量 | 可解释的硬约束与冲突处理 |
| 模型本身的记忆印象 | 用户自己的跨月 World 状态 |
| 单次 Prompt adherence | 角色、关系、时间线和版本的连续性 |

H3/H3 Max 应是 FM 的执行器层：

- `Preview`：H3 Max 或其他快速、低成本执行器。
- `Final`：H3 多参考/2K 或最适合当前 Contract 的执行器。
- `Fallback`：供应商不可用、审核限制、画风或价格不合适时切换。

## 5. 需要验证的 Fountain 信号

不要用“创建了多少 World”作为成功指标，优先观察：

```text
World 复用率 = 引用既有实体/参考集的生成数 / World 生成总数
接受资产复用率 = 后续被再次引用的 accepted 资产 / accepted 资产总数
接受成本 = 从第一次 Preview 到用户批准的全部有效调用成本
Canon 质量 = 用户保留的事实 / 自动提议事实
```

如果这些指标连续 4 周没有改善，说明 World 只是 UI 负担，应退回更轻的 Scratch，而不是继续增加对象类型。
